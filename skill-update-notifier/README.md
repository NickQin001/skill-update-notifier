# Skill 更新检查 · 0.2.1 用时检查

用户明确点名某个 Skill，或要求按该 Skill 工作时，在这次使用中检查这一个 Skill 的公开来源。也可以像以前一样，由用户主动要求做一次只读比较。

用时检查是文档约定、bot 职责或可选 Routine，不是平台钩子。不要把它理解成宿主会在工具调用后自动拦截。

**当前提供：**对点名 Skill 的用时检查；来源已确认时查阅公开 GitHub 或 SkillHub；获本次明确允许后，才用 CLI 只读比较本地目录。另有 Markdown/JSON 报告和人工更新建议。可选每日 Routine 只补充用时检查，不代替它。

**默认不读本机。** 用时检查和 Routine 都以公开来源为准。未读取本地时，不得声称「本地已是最新」。与本地安装比较需要用户在本次会话中明确允许。

**来源：** 只有 Skill 正文、已知安装记录，或用户本轮给出的原来源 URL / SkillHub slug，才比较上游。否则报告「来源未确认，跳过版本判断」，不猜测同名仓库。

**SkillHub：** 通过公开 API 核验版本记录、固定版本文件 SHA256、发布说明及可验证的公开文本差异；不要求下载或执行来源代码。发布说明是作者提供的信息，不是效果验证。

**本版不做：** 自动安装、覆盖已有安装、合并、回滚、使用频率采集、五次拒绝计数、持久提醒偏好。接入 SkillHub 公开 API 不等于本工具已获平台收录或审核。

## 安装与使用

把整个 `skill-update-notifier` 文件夹放入你的 AI 工具支持的 Skill 目录，保留 scripts 和 references。不需要配置钩子。Claude Code 的可选示例和 Grok Bot 的约定写在 [SKILL.md](SKILL.md) 附录里，都不是安装步骤。各宿主是否识别、是否允许执行 Python/Git，按实际环境核验；本版不宣称所有 AI 工具兼容。已有同名目录时先备份并审阅差异，不要直接覆盖。

随后可以这样说：

> 使用某个已点名的 Skill 完成我的任务。若要看更新，只查这个 Skill 的公开来源；不要读本机，不要安装或覆盖。来源不清楚就说明来源未确认。

想比较本机文件时，在同一次对话里明确允许读取那个目录，再运行 CLI。完整参数见 [usage.md](references/usage.md)。需要 Python 3.10+；GitHub 来源还需要 Git。没有第三方 Python 依赖，安装时保留 scripts 中两个脚本。

CLI 会读取你传入的本地目录，所以未获本次允许时不要运行它。第一次缺少历史基线时，即使文件不同也只报告差异，不宣称发现新版。输出的目标提交可人工保留为未来检查的观察基线；工具不自动写入该记录。

本地测试不能证明长期用户收益。请反馈：这次摘要是否帮助你决定更新或保留，以及决定的主要理由；反馈前删除本机路径和敏感内容。

SkillHub 按原始字节哈希比较，换行/BOM 差异也会计入；GitHub 文本比较忽略这些差异。SkillHub 额外安装元数据（例如下载包附带的 `_meta.json`）仍列为本地差异，不据此认定上游更新，不删除。
